# 小説執筆 (Novel Writer)

`novel-architect` が作成したプロジェクトを前提に、**各話（エピソード）単位**で原稿を執筆するスキル。

## 役割分担

| スキル | 担当 |
|--------|------|
| `novel-architect` | 設定、キャラ、世界観、章アウトライン（`Outline/outline-chapter-X.md`） |
| `novel-writer`（本スキル） | 各話原稿（`Chapters/第N話.txt`）、`Title.md` 管理 |

## 必須ルール（ユーザー指定）

- 小説の設定や概要、プロット作成までは `novel-architect` で作成。ここで作成されたファイルをもとに、各話の執筆を行う。
- AIによくある表現を使わない。特徴は `ai-checklist.md`（出典: `.cursor/agents/ai-checker.md`）を参照。
- 目標行数を達成するように努力する。行数は改行コード（`\n`）で計測。**憶測で適当な行数を報告することはNG**。
- タイトルの形式: `第N話 [タイトル]`
- その他、執筆に必要なルールは `novel-architect` を継承（`inherited-rules.md`）。
- **1行目**に各話のタイトル、**2行目から**執筆。
- **セリフの前後に空行**を追加する。
- **地の文の先頭は全角スペース**とする。
- ハングルや簡体字は使用しない。基本的に日本語で、一部英語を使う場合がある。
- **UTF-8** で必ず書く。
- ユーザーが各話の確認を行い **OK を出した後にのみ** 次の話の執筆を行う。**勝手に書き進めるのはNG**。
- わかりやすい表現を心がける。
- **話数は1から連番**（章をまたいで通し番号）。
- `Title.md` を作成・更新し、**章・話数・概要・行数**を記載する（形式: `title-template.md`）。
- `outline-chapter-X.md` の**対象話に沿って**執筆する。**勝手に内容を変更するのはNG**。
- 問題・疑問が生じたら**勝手に判断せず、必ずユーザーに確認**する。

### 禁止ワード

- 不器用

## 執筆前チェックリスト

```
- [ ] 小説プロジェクトのルートを特定した
- [ ] Chapters/README.md の目標行数を確認した
- [ ] 対象話が属する章の outline-chapter-X.md を読んだ
- [ ] Style.md / Characters.md / Worldbuilding.md / Synopsis.md を必要分読んだ
- [ ] 直前話（第N-1話.txt）を読み、連続性を把握した
- [ ] Title.md で話数・章の対応を確認した
```

## ワークフロー

### 1. 対象話の特定

1. ユーザーが指定した**通し話数 N**（未指定なら Title.md または `Chapters/` の最大番号+1 を確認し、ユーザーに確認）。
2. 全 `Outline/outline-chapter-*.md` を読み、**第N話**がどの章に属するか特定する。
3. 該当章アウトラインの「第N話」ビートのみを執筆範囲とする。アウトラインにない展開の追加・変更は禁止。

### 2. コンテキスト読み込み

プロジェクトルート（例: `小説/{作品名}/`）から読む:

| 優先 | ファイル |
|:---:|----------|
| 必須 | `Outline/outline-chapter-{章番号}.md`（対象話のビート） |
| 必須 | `Chapters/README.md`（目標行数） |
| 必須 | 直前話 `Chapters/第{N-1}話.txt`（N>1） |
| 推奨 | `Style.md`, `Characters.md`, `Worldbuilding.md`, `Synopsis.md`, `Timeline.md` |
| 任意 | `Genre.md`, `Conflict.md`、ジャンル別 `fantasy.md` / `mystery.md` |

### 3. 執筆

1. 感情的コア（その話で最も伝える感情）を1文で定義してから書き始める。
2. アウトラインのシーン順に、Show don't tell で肉付けする。
3. 出力先: `Chapters/第N話.txt`
4. ファイル構成:
   - 1行目: `第N話 [タイトル]`（アウトラインまたは Title.md のタイトル案に従う）
   - 2行目以降: 本文

### 4. 体裁（厳守）

```
第3話 タイトル例
　地の文は全角スペース1つで始める。

「セリフの前には空行」

「セリフの後にも空行」

　地の文に戻る。
```

- シーン転換: 地の文の段落間は空行1行。大きな場面転換は空行2行（`inherited-rules.md` 参照）。
- 「一」「二」「三」など数字による段落番号は使わない。
- 行数稼ぎの不自然な改行は禁止。

### 5. 行数の実測（必須）

執筆後、**必ずコマンドで計測**してから報告する。

```bash
python .cursor/skills/novel-writer/scripts/count_lines.py "小説/{作品名}/Chapters/第N話.txt"
```

PowerShell の場合:

```powershell
python .cursor/skills/novel-writer/scripts/count_lines.py "小説/作品名/Chapters/第N話.txt"
```

- 目標行数（`Chapters/README.md`）未満のときは、本文を肉付けして再計測。それでも不足する場合はユーザーに相談。
- チャットで報告する行数は、**上記コマンドの出力と一致**させる。

### 6. Title.md の更新

- プロジェクトに `Title.md` がなければ `title-template.md` に従い新規作成。
- 執筆完了後、対象話の行・概要・行数を更新する。
- 状態は「執筆済・確認待ち」などとし、ユーザーの OK 後に「承認済」へ。

### 7. ユーザー確認（ゲート）

執筆完了後、以下を提示して**停止**する:

- 保存パス
- **実測行数** / 目標行数
- アウトラインとの対応の要約（1〜3文）
- 確認依頼: 「内容をご確認ください。OK いただけたら次話に進みます。」

**ユーザーの OK なしに次話の執筆・保存を開始しない。**

### 8. 推敲・修正

ユーザーから修正指示があった場合:

- 差分のみ修正（ファイル全置換は避ける）。
- 修正後も行数を再計測して報告。
- アウトラインからの逸脱が必要なら、**先にユーザー確認**。

## AI表現の回避

執筆中・推敲時に `ai-checklist.md` を意識する。特に:

- 感情の要約・教訓的締め（「〜であったのだ」）
- 形容詞の飽和、マジックナンバー3、直喩の乱用
- 「微かな」「静寂」「運命」などの語彙偏り
- 物理的に不可能な並列行動、設定矛盾

## 判断を委ねるべきケース

以下は**執筆を止めて**ユーザーに質問する:

- アウトラインの話数と Title.md / 既存 Chapters の番号が一致しない
- 対象話のビートがアウトラインに存在しない
- 目標行数とアウトラインの分量が両立しない
- キャラ設定・世界観とアウトラインが矛盾する
- タイトル・話の帰属章が不明
