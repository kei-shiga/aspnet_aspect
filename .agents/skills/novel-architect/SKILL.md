# 小説家アーキテクト (Novel Architect)

純文学からあらゆる小説家のための包括的なスキルであり、忍耐強く感情に寄り添う対話を通じて、曖昧な物語のアイデアを構造化された小説プロジェクトへと変換します。

## コア哲学 (Core Philosophy)

**構築の前に内省を。物語の論理の前に、感情の真実を。**

このスキルの特徴:
- まず対話を通じて作業し、理解が完了した後にのみ執筆（ファイル保存）を行います。
- セクションごとにコンテンツを提案し、各ステップで承認を待ちます。
- 承認されたセクションをメモリ（記憶）に保存し、完了したときにのみファイルを一括で書き込みます。
- 他の何よりも、作者の「声」と「意図」を保護します。
- 沈黙、曖昧さ、および感情的な抑制を尊重します。

## 作成されるもの (What This Creates)

| ファイル/フォルダ | 目的 | フォーマット |
|-------------|---------|--------|
| `Braindump.md` | 感情的コアとビジョン | 北極星(North Star)、テーマ、構造 |
| `Genre.md` | ジャンルの期待値 | お約束、境界線、読者の期待 |
| `Style.md` | 語り口調とトーン | 声、リズム、ペース配分、影響を受けたもの |
| `Characters.md` | キャラクターシート | キャラクターごとのリッチなMarkdownテーブル |
| `Worldbuilding.md` | 設定と世界のルール | カテゴリ別の構造化されたテーブル |
| `Conflict.md` | ストーリーの葛藤と賭け金 | 内的/外的な葛藤 |
| `Synopsis.md` | ストーリー全体の概要 | 始まり、中間、結末 (500〜1000文字) |
| `Timeline.md` | ストーリーの時系列 | イベントの順序、ペース配分、連続性 |
| `Outline/` | 章ごとのビート（展開） | 章ごとの詳細なアウトライン |
| `Chapters/` | 原稿の草稿（ドラフト）ファイル | すぐに執筆可能な章ファイル |
| `Research/` | 参考資料 | メモ、情報源、コンテキスト |
| `Archive/` | 古いバージョンとカット部分 | 削除されたシーン、古い草稿 |
| `Assets/` | 視覚的な参考資料 | マップ、キャラクターアート、ムードボード |

## 出力場所 (Output Location)

プロジェクトは以下に作成されます:
```
~/writing/novels/{novel-name}/
```

すべての作業は同じ場所で行われます。このスキルは一度に一つのファイルを処理します。

## 使用パターンの例 (Usage Patterns)

### クイックスタート (コマンド方式)
```
/novel-architect an english novel named lost-horizon "A man discovers his small town is slowly disappearing from maps"
```

### インタラクティブな開始方法
```
"小説プロジェクトの作成を手伝って"
"小説の執筆を始めたいです"
"新しい本の設定をして"
```

どちらの形式でも、同じステップバイステップのインタビュープロセスが開始されます。

## 完全なプロセスの概要 (Complete Process Overview)

このスキルは以下の正確な順序に従い、絶対に先読み（スキップ）することはありません:

1. **プロジェクトの基礎事項の収集** → 名前、言語、コアとなるアイデア
2. **ディレクトリ構造の作成** → READMEつきのすべてのフォルダ
3. **インタラクティブなブレインダンプ** → 北極星、タイトル、テーマ、構造（セクションごとの承認）
4. **ジャンルの定義** → お約束、トーン、境界線、期待値
5. **声（語り口）の発見** → 視点（POV）、トーン、リズム、影響を受けたもの
6. **キャラクターの構築** → テーブル形式のリッチなキャラクターシート（一度に一人ずつ）
7. **世界観の構築** → 世界観構築テーブル（設定、雰囲気、ルール）
8. **葛藤のマッピング** → 内的/外的な葛藤、リスク（賭け金）
9. **シノプシス（あらすじ）の執筆** → ストーリー全体のアウトライン（始まり → 中間 → 結末）
10. **タイムラインの作成** → 時系列のイベントマップ
11. **章ごとのアウトライン生成** → 詳細なビートシート（一度に一章ずつ、静かに保存）
12. **すべての章の草稿（ドラフト）作成** → 第1章から第N章までを並行バックグラウンドタスク（推奨）で作成するか、順次作成するかユーザーに尋ねる
13. **各章のレビュー** → すべての章を並行バックグラウンドタスク（推奨）または順次処理する
14. **最終的な連続性チェック** → すべての章にわたる一貫性の検証
15. **完了と提示** → 最終確認と次のステップ

## 呼び出しタイミング

小説プロジェクトの作成、ストーリーアイデアのブレインストーミング、執筆プロジェクトのセットアップ時に使用してください。
