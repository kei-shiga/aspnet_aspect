# プロジェクト全般ルール

- **ルールの適用宣言**: 本ルールが正しく読み込まれていることを明示するため、各ターンの回答の冒頭に必ず「プロジェクトルールを適用します」と出力してください。
- 会話は全て日本語で行います。出力ファイルの内容も日本語で記述してください。

## 1. 指示語による行動の自動分岐（指示語の解釈）
- ユーザーからの指示語を解析し、使用ツールと行動範囲を厳密に制限すること。
  - "確認してください" / "調査してください" / "検討してください" / "説明してください"：読み取り専用ツール（read_file 等）および回答・報告の出力のみを許可。ファイルの変更やコマンド実行ツールの呼び出しを遮断すること。
  - "修正してください"：修正内容の事前提示を行った上で、局所編集ツール（edit_file 等）の実行を許可する。
  - 上記の判断ができない場合・指示内容が曖昧な場合：作業を停止し、質問のみを出力してユーザーの指示を仰ぐこと。

## 2. ファイル変更時のツール制約（差分保持ルール）
- 指示がないファイルやリソースの勝手な追加・修正・削除は行わないこと。
- **ツールの限定**: ファイル全体を書き換えるツール（write_file の上書き等）の使用を禁止し、ピンポイントな差分置換ツール（edit_file）を強制選択すること。
- **文脈の完全保持**: 指示されていない既存のコード、文章、設定、コメント、前後の文脈を「1文字も変更・省略・削除してはならない不変領域」として扱い、完全に保持すること。「気を利かせたつもりの変更」や「周辺の文脈・単語の巻き込み変更」は厳禁とする。
- **差分ノイズの排除**: 空行やインデントの勝手な整形を禁止し、エディタ上でユーザーが差分（Accept, Keep / Reject, Undo）を一目で判定できるよう、変更行数を最小限に抑えること。

## 3. コマンド実行・ファイル削除の2段階ゲート（事前確認ルール）
- 不可逆な変更やファイル消失を防ぐため、実行前に必ず確認待ちを挟むこと。
  - **コマンド実行**: 作業上コマンド（ターミナル／シェル操作）の実行が必要となった場合、AIの自己判断で勝手に実行してはならない。必ず事前に「実行する目的・用途」および「実行予定の具体的なコマンド」を提示し、ユーザーの確認・合意を得てから実行すること。
  - **ファイル削除**: 手段（コマンド実行、ツール等）を問わず、ファイルやディレクトリをAIの自己判断で勝手に削除することは厳禁とする。必ず事前に「削除する具体的な理由・目的」および「対象のパス」を提示し、ユーザーの確認・合意を得てから実行すること。

## 4. 思考の補完停止と指示の完全遵守（確認原則と歪曲禁止）
- **推測補完の停止**: 指示内容に不明点、曖昧さ、複数の解釈の余地、または不足している情報がある場合、AI自身の推測や独断の補完で作業を進めることは厳禁とする。不明点が完全に解消されるまで作業を停止し、必ず事前にユーザーへ質問・確認を行い、明確な回答・合意を得てから次の行動に移ること。
- **指示の忠実な再現**: 事前に提示・合意した内容に対して、AI独自の判断や推測で変更・歪曲・省略することは厳禁とする。必ず合意・指示された内容をそのまま忠実に実行すること。
- **遅延の防止**: すでに実行指示や合意が得られている事項について、不要な再確認を繰り返して実行を遅延させないこと。
