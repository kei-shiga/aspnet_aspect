# 画像生成ルール

- 画像生成を行う際は、そのツールで標準で使用できるモデル、または事前に取り決めたモデルを使用してください。

## 1. クォータ管理と運用ルール

本運用ルールは、Antigravity のようにシステム側の利用制限（クォータ）や中長期的なロック（100時間超の制限等）が掛かる環境・ツールを想定しています。予期せぬ利用制限やロックを回避するため、該当する環境では以下の運用を徹底してください。

1. 時間枠ごとの生成リクエスト上限
   - 成功・失敗（生成エラー）を問わず、以下のリクエスト（回数）を上限とする。
     - **1分間あたり**: 1リクエスト（バッチ処理の場合は待機。個別処理の場合は対象外）
     - **5時間あたり**: 9リクエスト
     - **1日（24時間）あたり**: 20リクエスト
     - 503エラーの場合はクォータの消費はないものとし、1時間の冷却時間を置くこととします。勝手に再実行するのはNGです。
   - 5時間枠で累計 8回に達した時点（または1日累計 18回に達した時点）で、AIはユーザーに対し「上限が近づいています。インターバル（または翌日への繰り越し）を置きますか？」と警鐘を鳴らし、継続の是非を確認すること。
2. 1シーン（または1キャラクター）あたりの修正回数
   - 1つの画像に対し、修正のリクエストは最大 3回までとする。
   - 同一シーンで試行が2回に達した場合、3回目を行う前に必ず「残りのクォータ数」を提示し、継続か再考かの判断を仰ぐ。
   - 3回を超えても理想の画像が得られない場合は、回数制限を盾に作業を打ち切るのではなく、「一旦立ち止まってプロンプトを根本から見直す」ために生成を中断し、原因の検証を優先する。
3. 独断による複数実行・連続実行の禁止
   - 1度の返信（ターン）内で、ユーザーの明確な合意なく画像生成ツールを複数回、または連続して実行しない。
4. エラー発生時の強制冷却期間
   - 「画像が生成されない」「セーフティフィルタによる中断」などのエラーが 2回連続 で発生した場合、フィルタ検知の累積を避けるため、最低 1時間 は画像生成の全機能を停止（冷却）させ、プロンプト（指示文）を根本から見直す。
5. プロンプト生成前の「構成案」提示と自己点検（プリフライト・チェック）
   - AIは実際に画像を生成する前に、必ず**「プロンプトに盛り込む要素（体格、服装、背景、表情など）」を箇条書きでユーザーに提示し、合意を得る**こと。
   - これにより、指示の漏れや解釈の相違による不必要なリトライ（リソース消費）を最小限に抑える。
   - 生成リクエスト送信前に、以下の項目を自律的に検証（プリフライト・チェック）し、対話内でその結果を提示すること。
     - **パスの完全性**: 保存先フォルダ・ファイル名が実在し正しいか（推測せず実在を確認）。
     - **技術的制約**: 参照画像数やAPI仕様・引数制限を逸脱していないか。
     - **指示の網羅性**: ユーザーからの最新の修正指示がすべて反映されているか。
6. 残数報告の義務化
   - 画像生成を行う際、および生成前後のやり取り（構成案の提示や状況確認など）において、必ず「5時間枠：○回目（残り○回）／ 本日：○回目（残り○回）」というステータスをユーザーに報告すること。
   - これにより、ユーザーとAIの間で常にクォータの残数を同期し、予期せぬロックを回避する。

## 2. バージョン管理と制作共通ルール

### ディレクトリ構造とパス規則
画像関連ファイルは必ず以下のパス規則に厳密に従って配置すること。
- **種類（`{種類}`）**: `Characters`（人物）、`Back`（背景）、`Scene`（場面・挿絵）
- **対象名（`{対象名}`）**: キャラクター名、背景名、シーン名（例: `ヴィンセント`, `王城の会議室`, `アメリア_馬車内`）
- **生成物・作業パス**: `Images/{種類}/Versions/{対象名}/v_N.png`
- **制作ログパス**: `Images/{種類}/Versions/{対象名}/log.md`
- **本番配置パス**: `Images/{種類}/{対象名}.png`

1. **上書き保存の完全禁止**
   - 全ての生成物は必ず `Images/{種類}/Versions/{対象名}/v_N.png`（`v_1.png`, `v_2.png`...）へナンバリング保存し、既存ファイルを直接上書きしないこと。
   - ユーザーから明示的な最終承認（OK）を得たバージョンのみを、本番用ファイル（`Images/{種類}/{対象名}.png`）へコピー・配置すること。
2. **制作ログ（log.md）の厳格な維持・更新義務**
   - 試行のたびに、対象のログファイル（`Images/{種類}/Versions/{対象名}/log.md`）へ以下を即時追記すること。
     - **実プロンプト**: 生成に用いた生指示文（英文等）を捏造なくすべて記載する。
     - **却下・不備理由**: ユーザーからの指摘内容を要約せず、原文のまま記録する。
   - **記録失敗時の即時報告**: ツールエラー等でログの更新に失敗した場合は、生成作業を即座に中断し、その事実をユーザーに報告して指示を仰ぐこと。
3. **構図・品質規約**
   - **文字排除（No Text）**: 画面内の背景、小物、衣類すべてにおいて文字や記号が含まれないようにする。
   - **視線とアクションの一致**: 登場人物の目線が指示された対象を正確に捉えているか確認する。
   - **解像度・アスペクト比**: 1024×1024 をデフォルトとし、指定に応じて 700×1000（縦長）、1408×768（横長）等を設定する。

## 3. キャラクター設定のマスターデータ照合

- キャラクターの視覚情報（身長、体格、肌の色、髪型等）は、プロジェクトのマスターデータ（設定資料・Characters.md 等）を絶対的な正解として遵守すること。
- 生成ごとに必ずマスターデータを読み込み、照合を行って差異を排除すること。
